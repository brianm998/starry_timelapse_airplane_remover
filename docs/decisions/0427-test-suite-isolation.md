# 0427: make a hung pipeline test fail with a stack; test-desktop's results file

Cause (hang): not reproduced. Alone the test passes in 11 s and under `mason run --needs test-suite` in 6 s. Its rig engine uses `remote="origin"` (a local bare repo), so the fetch is not the network. Unproven candidates: `Hold.granted()` iterating the fake `mason hold` stdout with no timeout (masonq.py), or an Apple-unsigned binary stalled by a syspolicyd crash loop.
Choice: do not guess a source fix. Bound the test's `gather` with `wait_for(..., 60)` and set `faulthandler_timeout = 120` in pytest config, so a recurrence prints every thread's stack and fails instead of blocking the suite and leaving no exit file.
Results file: `star-desktop/build.gradle.kts` is unchanged and still writes `build/test-results/test-all.xml`. Nothing in `pipeline/` touches `star-desktop/build` (tests use tmp_path; heavy.py and watch.py kill by pgid/pid). The directory mtime equals the exit-file time, so the removal happened when MASON stopped the hung test-pipeline suite and cleaned up the run. That logic is in the mason repo, not here. Follow-up for it: judge each suite from its own results before cleaning up a stopped sibling. With a hang now bounded, test-pipeline ends on its own and test-desktop's verdict no longer waits on it.
