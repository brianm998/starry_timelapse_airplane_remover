# s149: dark appearance for system-drawn dialogs (task #159)

Summary: On macOS the gui forces `NSApp.appearance` to dark aqua at launch and the desktop client sets `apple.awt.application.appearance` to dark aqua, so system-drawn alerts, panels and AWT dialogs come up dark on a Light-mode Mac.

## What changed

- `gui/star/AppDelegate.swift`: `forceDarkAppearance(_:)` sets `app.appearance = .darkAqua`; `applicationWillFinishLaunching(_:)` calls it before the first window exists.
- `gui/starTests/starTests.swift`: `DarkAppearanceTests.testTheAppForcesTheDarkAppearance` runs the launch hook, checks `NSApp.appearance?.name == .darkAqua` and that a fresh `NSAlert`'s window resolves to dark aqua. `tearDown` resets `NSApp.appearance` for the shared test host.
- `star-desktop/src/main/kotlin/com/star/desktop/Main.kt`: `applyMacDarkAppearance(osName, setProperty)` sets `apple.awt.application.appearance=NSAppearanceNameDarkAqua` only when `DesktopOs.of(osName) == MAC`. It is the first statement of `main`, so it runs before AWT starts and before `--self-test` or `runApp`.
- `star-desktop/src/test/kotlin/com/star/desktop/ui/app/MacDarkAppearanceTest.kt`: macOS sets the property; Windows and Linux leave it alone.

No user-visible strings were added or changed, so the localization catalogue is untouched and there is no Kotlin/Swift wording to keep in step.

## Not changed

- Windows' and Linux's folder pickers, and the Swing `JFileChooser` fallback: out of scope per the task.
- Sheets with no background of their own: the second ticket of the pair.
- Red error cards: red on purpose.

## Checks

- `scripts/exit/s149.sh` runs the gui unit test and the desktop unit test with `STAR_USE_GPU_FOR_MERGE=0`.
- The "before any window" property (A3) is a review check: both hooks run before any window is created.
