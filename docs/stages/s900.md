# s900: a Start right after a Stop is never dropped silently

Summary: A build dropped by a cancel now calls a `cancelledClosure` (wired in the gui, stard and cli), and the gui orders Stop's cancel before the next Start, so a Start after a Stop runs or says it did not.

`FrameGraphBuilder.build` returned without calling anything when a cancel moved `cancelGeneration` while it built its graph, leaving the gui in "processing" for good. The gui's `stopProcessing` cancel was an unstructured Task that could land after the next build had entered. Tests: `StopThenStartTests`, `FrameGraphBuilderCancelTests`. No catalogue keys, no Kotlin change (the desktop already handles stard's `cancelled` state).
