# s245: GPUOpsTests skip under the forced CPU merge; build-gui finds its signed app

Summary: GPUOpsTests skip when `STAR_USE_GPU_FOR_MERGE=0` forces the CPU merge (GPU tests are CI-only on this Mac), and `build-gui` now builds into `-derivedDataPath` and checks `Star.app`, so its signing check finds the app.

`GPUOpsTests.setUpWithError` calls `XCTSkipIf(GPUCapability.mergeForcedOff(), …)` before the GPU availability skip. CI does not set the variable, so the suite still runs there.

build-gui was red for two reasons outside the test change. This Mac's Xcode has `IDECustomDerivedDataLocation` set, so it ignores `-derivedDataPath` and builds under `gui/DerivedData`. Also, the check looked for `star.app`, but the product is `Star.app`, and `/Volumes/sp` is case-sensitive APFS. Now `.mason/scripts/xcodebuild-signed.sh` pins `SYMROOT`/`OBJROOT` (as absolute paths) under any `-derivedDataPath` it is given, and `check-gui-signing.sh` defaults to `.build/gui-dd/Build/Products/Debug/Star.app`, keeping the `gui/DerivedData` fallback. Verified: the build-gui command run by hand ended `SIGNING-CHECK-OK` and `BUILD-build-gui-OK`.
