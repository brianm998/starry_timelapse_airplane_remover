# s245: GPUOpsTests skip under the forced CPU merge

Summary: GPUOpsTests skip when `STAR_USE_GPU_FOR_MERGE=0` forces the CPU merge, and a new GPUMergeForcedOffTests proves every merge and warp entry point asked for the GPU then runs on the CPU.

`GPUOpsTests.setUpWithError` calls `XCTSkipIf(GPUCapability.mergeForcedOff(), …)` before the GPU availability skip. CI does not set the variable, so the suite still runs there.

Skipped tests are absent from the xunit file, so skipping the class's tests dropped the local `test-StarCpp` count from 254 to 250 and the suite failed its `min_tests`. The answer is not a lower floor (and `.mason/` on a branch changes nothing). The other half of the skip is now tested instead: `GPUMergeForcedOffTests`, which runs only when the variable forces the CPU (so it skips on CI). For `alignAndMedianMerge`, `medianMergeImage`, `debugMedianMerge` and `debugWarp` called with `useGPU: true`, it checks that `GPUOps.mergeCounts()` does not move and that the bytes match the `useGPU: false` result. It uses inputs where the GPU and CPU arithmetic differ. Those four tests bring the local count back to 254.

build-gui was red on this branch for reasons outside the test change. `develop` has since fixed that in 975fe711, so this change takes `develop`'s versions of the `.mason` files and touches nothing under `.mason/`.
