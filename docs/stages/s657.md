# s657: Gherkin mac gui shard 1 died at CompileAssetCatalogVariant (task 642)

Summary: The mac gui Gherkin build died in actool/ibtoold compiling `StarIcon.icon`, so shard 1's four features never ran; the gui Gherkin step now retries the build once on that failure only (root cause on the runner unproven).

## What was found

- CI log: `CompileAssetCatalogVariant ... failed`, then `Terminate orphan process: ibtoold`. No actool message survives in the tail.
- The only recent change to those inputs is s588 (`7136c5e0`), which replaced `AppIcon.appiconset` with `gui/star/StarIcon.icon`.
- Locally, `xcrun actool --app-icon StarIcon gui/star/StarIcon.icon gui/star/Assets.xcassets` succeeds and emits `Assets.car` and `StarIcon.icns`. So the bundle is valid; a content bug is not shown.
- A full local Release build could not run in this sandbox (SwiftPM cannot clone Semaphore: no network), so the universal "thinned" variant on Xcode 26.3 was not reproduced.

## Change

`.github/workflows/gherkin.yml`: the gui step retries once when the log shows the asset-catalogue/ibtoold failure and no test had executed. The first attempt's log is kept as `gherkin-gui-attempt1.log`. Test failures are never retried.

## Not done / next
