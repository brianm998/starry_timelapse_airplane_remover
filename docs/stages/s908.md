# s908: the gui loads outlier groups for a window of frames, not all of them

Summary: Opening a sequence no longer loads every frame's full outlier groups: each frame reads its decision counts from a small `OutlierCounts.json`, and full groups load only for the current frame plus or minus 3 and the grid selection, and are released outside radius 4 unless the frame has an unsaved edit.

`OutlierGroups.write` writes `OutlierCounts.json` beside the paint data; a sequence without it is loaded once, which writes it, and released. `FrameOutlierProcessor.releaseOutlierGroups` refuses while a load is in flight or the frame is `.userModified`. `ImageSequenceViewModel.updateOutlierWindow` serialises loads and releases; apply-decision-tree-to-all loads the neighbours of each frame and releases behind it. stard already loads per request, so no daemon, Kotlin, proto or catalogue change. Changing the grid selection also runs `updateOutlierWindow`, so a newly selected far frame loads its groups. Apply-decision-tree-to-all now marks a frame changed only when the tree changed one of its decisions, so unchanged frames are not saved again and can be released behind the sweep; it returns its task so a test can await it. Tests: `OutlierCountsSummaryTests` (StarCore), `OutlierWindowTests` (gui: window arithmetic, A1-A4 on a 12-frame fixture with stored groups, selection loading and releasing, and the apply-to-all sweep releasing unedited frames while keeping an edited one).

`OutlierCountsSummaryTests` first failed to compile: it called `OutlierGroup.set(shouldRemove:)`, which belongs to `OutlierRemovalObserver`; the group's setter is `shouldRemove(_:)`. `OutlierWindowTests` then failed to compile because `Coord` lives in `StarCppBridge`, which the gui test target has to import itself (`import StarCore` does not re-export it).

No exit script.
