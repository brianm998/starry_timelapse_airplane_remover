# s908: the gui loads outlier groups for a window of frames, not all of them

Summary: Opening a sequence no longer loads every frame's full outlier groups: each frame reads its decision counts from a small `OutlierCounts.json`, and full groups load only for the current frame plus or minus 3 and the grid selection, and are released outside radius 4 unless the frame has an unsaved edit.

`OutlierGroups.write` writes `OutlierCounts.json` beside the paint data; a sequence without it is loaded once, which writes it, and released. `FrameOutlierProcessor.releaseOutlierGroups` refuses while a load is in flight or the frame is `.userModified`. `ImageSequenceViewModel.updateOutlierWindow` serialises loads and releases; apply-decision-tree-to-all loads the neighbours of each frame and releases behind it. stard already loads per request, so no daemon, Kotlin, proto or catalogue change. Tests: `OutlierCountsSummaryTests` (StarCore), `OutlierWindowTests` (gui, window arithmetic only).

Not verified here: the sandbox could not fetch SwiftPM packages, so nothing was built or run. A gui test that counts `loadOutliers` calls on a real fixture is not written.

No exit script.
