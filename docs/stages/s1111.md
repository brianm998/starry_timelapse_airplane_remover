# s1111 — stopped-run alert without the resume command

Summary: The "Previous Run Stopped" alert in both clients no longer prints a `star <config path>` command: Restart Now sits above OK when the run can be picked up, and a sentence says so when it cannot.

Task #1131. Decision: docs/decisions/1100-stopped-run-alert-text.md. Exit: scripts/exit/s1111.sh.

- `RunMarker.briefReport` adds `run_marker.brief.not_restartable` only when the marker named a config that is gone.
  `run_marker.brief.resume` is deleted from all 22 catalogues. The cli's full `report` is unchanged.
- gui: a system alert puts the two buttons side by side (measured on macOS 15.8), so a restartable report is shown
  by `StoppedRunSheetView`, stacked, OK the default. Every other critical warning stays the system alert.
- desktop: `CriticalWarningDialog` stacks the two buttons full width, Restart Now on top; OK stays the default.
- Test rounds went red on node marmot for environment reasons (no `uv`; no linked OpenCV, so StarCpp
  cannot compile). Those are filed as a separate proposal, not changed here.
