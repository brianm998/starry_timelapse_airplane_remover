# s829: GPU merge turned off after a run dies mid-merge (task #854)

Summary: A run that dies while a Metal merge is in flight is recorded in its run marker, and the next gui or desktop session turns `useGPUForMerge` off and shows a `gpuMergeTurnedOff` warning saying why; the user can turn it back on.

`GPUOps.mergesInFlight` counts merges holding a GPU slot; `RunMarker` gains optional `gpuMergesInFlight` and `gpuMergeEnabled` and `diedDuringGPUMerge`. The gui (`ViewModel.reportAbandonedRuns`) and stard (`AbandonedRunReports`, sent after `previousRunDied`) report it; the desktop's `GpuMergeTurnedOff` flips the shared pref. Three catalogue keys translated in all 22 tables.

`OpenCVQoSTests` gains `testParallelForUsesMoreThanTheCallingThread`, which runs on Intel too: the width test skips on x86_64, which left `test-StarCpp-qos` with 2 runs against its floor of 3 on this iMac Pro. The new test checks that the inheritance tests are not passing only because `cv::parallel_for_` never left the calling thread.
