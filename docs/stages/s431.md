# s431: pr-gate/static red on develop (task #433)

Summary: `Train._pick` read the ready tickets before the active batches, so a pick racing the worker-thread abandon of a red batch saw no ready member in a split half, dropped both halves, and then batched both tickets together; it now reads the active batches first.

Cause: `_give_up_red` abandons on a thread (tickets go `ready`, then the batch ends) while `step` runs on the loop. A `_pick` that listed ready tickets while the batch was active and listed active batches after it ended found the half empty and popped it. CI saw batches 2=[1,2], 3=[].
Fix: `flying` is computed before `ready` in `_pick` (train.py).
Test: `test_split_halves_survive_a_pick_that_races_the_abandon` (fails on the old order); `test_fix_answer_splits_batch` unchanged.
