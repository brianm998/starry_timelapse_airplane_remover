# App icons

`star.icns` / `star.ico` / `star.png` are the old-style (824/1024 margin) form of the macOS gui's icon, converted to each OS's native
format for jpackage (via `nativeDistributions { macOS/windows/linux { iconFile.set(...) } }`
in `build.gradle.kts`). They are generated, not hand-made: `python3 art/export.py` rebuilds them
(and the gui's Icon Composer bundle `StarIcon.icon`, which jpackage cannot use) from `art/masters/BR-1.png` (128 px and up) and `BR-2.png`
(16 to 64 px, drawn to read small). The body is 824/1024 of the canvas (Apple's grid), also in the
`.ico`; `star.png` (Linux, no OS margin) is BR-1 at 512 px with the body at 94%. `.icns` and `.ico`
are written in pure Python, so `python3 art/export.py --check` runs anywhere. Sizes: icns 16-1024,
ico 16, 24, 32, 48, 64 (BR-2) and 128, 256 (BR-1).

# Folder choosers need no bundled native library

On Windows the folder picker is Explorer's own (`IFileOpenDialog`), reached by running the
`folder-picker.ps1` resource through `powershell.exe`, which ships with Windows. On Linux it is
`zenity` (else `kdialog`) from the system, so the `.deb` does not bundle or depend on a chooser:
a machine without either falls back to Swing's `JFileChooser`. See `ui/initial/FolderPickers.kt`.

# DMG background and the Windows side panel

`packaging/dmg/` is jpackage's resource directory for `packageDmg` / `packageReleaseDmg`: the Compose plugin
has it as a protected `jpackageResources` (`--resource-dir`), set by reflection per task in `build.gradle.kts`. The lookup is tolerant: if the property can't be found or accessed it logs a warning naming the Compose version and keeps jpackage's default layout. jpackage picks up
`Star-background.png` (BR-7a, 144 dpi so Finder shows it at 793x496 pt) and `Star-dmg-setup.scpt` (replaces its
default Finder script: app in the left third, Applications link in the right third). Both are generated by
`python3 art/export.py`. The script runs Finder, so it only runs on the CI macos jobs, never on a dev Mac
you are not watching. Signing and notarisation come after packaging, so the layout survives.

The Windows installer has no BR-7b side panel. jpackage's `.exe` goes through WiX; the only hook is replacing
`main.wxs` in the resource dir with a copy of the JDK's default plus a `WixUIDialogBmp` variable. That cannot be
written or verified without a Windows machine, and a wrong `main.wxs` breaks the installer, so the image is left out.
